# Sentra: мониторинг серверов и сети

Коробочный мониторинг для малого бизнеса. Ставится одной командой, сервер подключается одной командой, графики появляются через минуту. Без шаблонов, макросов и ключей PSK.

Версия 0.3: Linux-серверы через агент, Proxmox VE через API, журнал проблем, доступность за 30 дней, режим обслуживания, обзор плитками или таблицей, графики за час, сутки, неделю и месяц.

## Установка коробки

Нужен Linux-сервер или VM (Ubuntu, Debian, CentOS/Alma): 2 vCPU, 2 ГБ RAM, 20 ГБ диска, доступ в интернет на время установки. Docker скрипт поставит сам.

```bash
curl -fsSL https://raw.githubusercontent.com/AbuBakrVu/Sentra/main/install.sh | sudo bash
```

Скрипт скачает код в `/opt/sentra`, определит IP сервера, соберёт и запустит коробку. В конце он покажет адрес панели и пароль администратора.

Если у сервера несколько адресов, укажите нужный явно:

```bash
curl -fsSL https://raw.githubusercontent.com/AbuBakrVu/Sentra/main/install.sh | sudo SENTRA_IP=192.168.1.10 bash
```

Откройте адрес из вывода скрипта. Браузер предупредит о самоподписанном сертификате: это нормально для локальной сети, подтвердите исключение. Войдите как `admin` и смените пароль в разделе «Настройки».

**Обновление:** запустите ту же команду ещё раз. Настройки, устройства и история графиков сохранятся.

После установки на сервере есть команда `sentra`:

| Команда | Что делает |
| --- | --- |
| `sudo sentra info` | Адрес панели, логин и пароль первого входа |
| `sudo sentra update` | Обновить до свежей версии из GitHub |
| `sudo sentra status` | Состояние контейнеров |
| `sudo sentra logs` | Журнал сервера |
| `sudo sentra restart` | Перезапустить коробку |

Наружу коробка открывает только порт 443. VictoriaMetrics доступна только внутри Docker-сети.

<details>
<summary>Установка вручную</summary>

```bash
git clone https://github.com/AbuBakrVu/Sentra.git /opt/sentra
cd /opt/sentra
cp .env.example .env && nano .env     # IP коробки в SENTRA_PUBLIC_URL и SENTRA_CERT_HOSTS
docker compose up -d --build
docker compose logs sentra | grep пароль
```

## Подключение сервера

1. В панели откройте «Добавить сервер», скопируйте команду.
2. Выполните её на подключаемом сервере (нужны sudo, systemd и `curl`).
3. Сервер появится в панели сам.

Команда действует 24 часа, по ней можно подключить несколько серверов. Повторная установка на тот же сервер не создаёт дубль: сервер узнаётся по `/etc/machine-id`.

Как устроена безопасность подключения:

- В команде есть отпечаток ключа коробки. `curl --pinnedpubkey` скачивает скрипт и агент, только если ключ совпадает, поэтому подменить коробку в сети не выйдет.
- Агент запоминает тот же отпечаток и дальше разговаривает только с этой коробкой.
- После регистрации у агента свой постоянный ключ. Токен из команды больше не нужен.
- Агент только отправляет данные. Входящие порты на серверах открывать не нужно.

Полезное на сервере с агентом:

```bash
systemctl status sentra-agent
journalctl -u sentra-agent -n 50
sentra-agent collect          # разово показать, что собирает агент
```

Удалить агент: `systemctl disable --now sentra-agent && rm /usr/local/bin/sentra-agent /etc/systemd/system/sentra-agent.service && rm -r /etc/sentra`.

## Подключение Proxmox

Sentra читает Proxmox VE через API, на узлы и в машины ничего ставить не нужно. Появляются все узлы кластера, виртуальные машины (QEMU), контейнеры (LXC) и хранилища. Новые машины добавляются сами, удалённые помечаются «Нет в Proxmox».

1. На любом узле создайте пользователя с правами только на чтение и токен:

   ```bash
   pveum user add sentra@pve --comment "Sentra monitoring"
   pveum aclmod / -user sentra@pve -role PVEAuditor
   pveum user token add sentra@pve monitor --privsep 0
   ```

   Последняя команда покажет `full-tokenid` (`sentra@pve!monitor`) и `value` (секрет). Секрет показывается один раз.
2. В панели: «Добавить» › «Proxmox». Укажите адрес любого узла (`192.168.1.20`, порт 8006 подставится сам), ID токена и секрет.
3. Через минуту узлы и машины появятся на обзоре, сгруппированные по узлам.

Коробке нужен доступ к порту 8006 узла. В кластере достаточно одного узла: Sentra увидит все.

Что собирается каждые 30 секунд:

| Объект | Метрики |
| --- | --- |
| Узел | CPU, память, swap, load average, корневой раздел, каждое хранилище (local, local-lvm, NFS, ZFS…) |
| Виртуальная машина | Включена или выключена, CPU, память, сеть |
| Контейнер | Включён или выключен, CPU, память, заполнение диска, сеть |

Заполнение диска внутри виртуальной машины Proxmox отдаёт только через гостевой агент QEMU, это будет в следующей версии. Если нужен полный набор метрик внутри ВМ, поставьте в неё агент Sentra.

Сертификат Proxmox самоподписанный, поэтому Sentra при первом подключении запоминает его отпечаток и дальше доверяет только ему. Если сертификат сменился (переустановка узла, перевыпуск), подключение покажет ошибку. Если вы сами меняли сертификат, нажмите «Принять новый сертификат».

## Проблемы и доступность

Sentra не просто показывает текущие цифры, а ведёт журнал: когда проблема началась, когда закончилась, кто взял её в работу. Журнал хранится 90 дней.

| Проверка | Внимание | Авария |
| --- | --- | --- |
| Нет данных от агента или Proxmox | — | больше 3 минут |
| Узел Proxmox не в сети кластера | — | сразу |
| CPU | больше 85% 10 минут | больше 95% 10 минут |
| Память | больше 85% 10 минут | больше 95% 5 минут |
| Диск или хранилище | больше 85% | больше 95% или свободно меньше 2 ГБ (на разделе от 20 ГБ) |

Короткие всплески проблемой не считаются. Проблема закрывается, когда значение опустится немного ниже порога, чтобы не было «мигания».

**Доступность за 30 дней** — полоса из 30 квадратов у каждого устройства и процент. Простоем считается только «нет связи» и «узел не в сети». Высокий CPU или заполненный диск — это предупреждение, а не простой. Время, когда машина выключена в Proxmox, в процент не входит.

**Взять в работу** — на странице «Проблемы» или в карточке устройства, с комментарием. Остальные видят, кто занимается проблемой.

**Режим обслуживания** — в карточке устройства на 1 час, 4 часа или сутки. Пока он включён, новые проблемы не заводятся. Режим снимается сам по истечении срока.

| Статус | Когда |
| --- | --- |
| Авария | Есть открытая авария |
| Внимание | Есть открытое предупреждение |
| Нет связи | Нет данных больше 3 минут |
| Выключена | Машина остановлена в Proxmox. Это не проблема |
| Ждём данные | Агент зарегистрирован, метрик ещё нет |

## Интернет-канал

Коробка раз в 30 секунд проверяет командой ping роутер и внешние адреса (по умолчанию DNS Яндекса, Google и Cloudflare). Проверка включена сразу после установки, отдельный агент не нужен.

- Интернет считается недоступным, когда две проверки подряд не получили ответа ни от одного внешнего адреса. Начало перерыва ставится по первой неудачной проверке.
- Укажите адрес роутера на странице «Интернет»: тогда в журнале видно, отвечал ли роутер во время сбоя. Если отвечал, причина у провайдера, если нет, в локальной сети.
- Предупреждения: потери пакетов больше 3% и задержка больше 150 мс (среднее за 5 минут).
- Кнопка «Скачать отчёт для провайдера» выгружает журнал перерывов в CSV для Excel за 7, 30 или 90 дней.
- Если адрес не отвечает на ping, коробка перепроверяет его TCP-соединением: в некоторых сетях ICMP закрыт.
- Время, когда сама коробка была выключена, в журнал не попадает.

## Экран на стену и сводка для директора

Обе страницы открываются из меню пользователя (кружок с буквой справа вверху).

- **Экран на стену** (`/wall`): тёмная страница без меню с крупным вердиктом, списком проблем и плитками устройств. Обновляется раз в 15 секунд, есть кнопка «Во весь экран».
- **Сводка для директора** (`/brief`): одна страница без графиков: что на связи, работает ли интернет, сколько было проблем и простоев за 30 дней. Кнопка «Распечатать» убирает меню и кнопки.

## Проверка на большом парке: поддельный Proxmox

В образ коробки входит `sentra-pvemock`: он отвечает на запросы Sentra как настоящий Proxmox VE, только узлы и машины выдуманные, а их нагрузка меняется сама. Так можно посмотреть, как Sentra ведёт себя на сотнях машин, не имея такого кластера.

```bash
cd /opt/sentra
docker compose exec -d sentra sentra-pvemock -listen 127.0.0.1:8006 -nodes 4 -vms 120
```

Затем в панели: «Добавить › Proxmox», адрес `127.0.0.1:8006`, ID токена `test@pve!mock`, секрет любой, длиннее 8 символов.

Флаги: `-nodes` — узлов, `-vms` — машин всего, `-stopped 0.12` — доля выключенных, `-delay 200ms` — задержка ответа, как у медленного кластера, `-seed` — зерно (одинаковое зерно даёт тот же кластер).

Сценарии сбоев запускаются запросами к заглушке:

```bash
M='docker compose exec sentra wget -qO- --no-check-certificate'
$M 'https://127.0.0.1:8006/mock'                      # что сейчас происходит
$M 'https://127.0.0.1:8006/mock?vm=105&cpu=98'        # машина 105 грузит CPU на 98%
$M 'https://127.0.0.1:8006/mock?vm=105&mem=93'        # память занята на 93%
$M 'https://127.0.0.1:8006/mock?vm=105&stop=1'        # выключить (start=1 — включить)
$M 'https://127.0.0.1:8006/mock?vm=105&gone=1'        # машина пропала из кластера
$M 'https://127.0.0.1:8006/mock?node=pve2&offline=1'  # узел выпал из кластера (online=1 — вернуть)
$M 'https://127.0.0.1:8006/mock?reset=1'              # убрать все сценарии
```

Правила на CPU и память срабатывают через 10 минут перегрузки, а не сразу. Заглушка живёт до перезапуска контейнера. После проверки удалите подключение в «Настройках», иначе в истории останутся выдуманные машины.

## Резервная копия

Всё состояние лежит в двух томах Docker: `sentra-data` (настройки, пользователи, устройства, ключ сертификата) и `vm-data` (метрики). Ключ сертификата важно сохранить: если он сменится, агенты перестанут доверять коробке и их придётся подключать заново.

```bash
docker run --rm -v sentra_sentra-data:/d -v $PWD:/b alpine tar czf /b/sentra-data.tgz -C /d .
```

## Разработка

```
cmd/sentra-server     точка входа сервера
cmd/sentra-agent      точка входа агента
internal/server      API, хранилище (SQLite), TLS, клиент VictoriaMetrics
internal/agent       сбор метрик Linux из /proc, регистрация, отправка
internal/proxmox     клиент API Proxmox VE
internal/proto       формат обмена агент ↔ сервер
web/                 интерфейс (React + Vite + uPlot), встраивается в бинарник сервера
```

Локальный запуск: запустите VictoriaMetrics на `127.0.0.1:8428`, затем `make run`. Панель будет на `https://127.0.0.1:8443`. Для правки интерфейса с горячей перезагрузкой: `cd web && npm run dev` (запросы `/api` проксируются на сервер).

Переменные окружения сервера:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `SENTRA_LISTEN` | `:443` (в образе `:8443`) | Адрес и порт HTTPS |
| `SENTRA_DATA` | `/var/lib/sentra` | База, сертификат, ключ |
| `SENTRA_VM_URL` | `http://127.0.0.1:8428` | VictoriaMetrics |
| `SENTRA_PUBLIC_URL` | из адресной строки | Адрес для команды подключения |
| `SENTRA_CERT_HOSTS` | пусто | IP и имена в сертификате |
| `SENTRA_AGENTS_DIR` | `/opt/sentra/agents` | Бинарники агентов для скачивания |
| `SENTRA_ADMIN_PASSWORD` | случайный | Пароль admin при первом запуске |
